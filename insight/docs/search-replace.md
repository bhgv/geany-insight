# Поиск и замена: режимы и языки запросов

Сначала выберите область поиска. Одни и те же знаки имеют разный смысл в
текстовом поиске, фильтре символов и маске имени файла. Context доступен только
для чтения; замена выполняется в редакторе.

## Области и команды

| Где | Область и действия | Язык запроса |
| --- | --- | --- |
| Найти (`Ctrl+F`) | Текущий редактор; далее/назад; найти все в документе или сеансе; отметить | Обычный текст или регулярное выражение GLib |
| Заменить (`Ctrl+H`) | Одна замена; все в документе, выделении или открытом сеансе | Текст или regex; ссылки на группы в строке замены |
| Быстрый поиск в файле | Текущий редактор; предыдущее/следующее | Текст, `~подпоследовательность`, Regex |
| Лупа в Context (`Ctrl+F` при фокусе в Context) | Только предпросмотр; далее/назад, `F3` / `Shift+F3` | Текст, `~подпоследовательность`, Regex; замены нет |
| Поиск по проекту, папке, выбранным файлам | Файлы проекта, открытые документы, текущий документ, выбранные файлы/папка; маски путей | Текст, нечёткий поиск, Regex либо Keywords/Boolean |
| Употребления / Relations | Индексированные символы или лексические употребления/вызовы; Code only исключает строки/комментарии поддерживаемых языков | Имя символа с ограничениями языка/владельца; это не переименование |
| Фильтры символов и файлов | Фильтрация списка без правки текста | Специальный язык фильтров ниже |
| Поиск в справке (`Ctrl+F`) | Текущая страница; `F3` / `Shift+F3` | Текстовый поиск, не regex редактора |
| Старый Geany Find in Files, если вызван | Дисковые файлы через настроенный grep | Буквальный `grep -F` либо расширенные выражения `grep -E`, не GLib/PCRE |

Case учитывает регистр; Word требует целого слова. Word start в стандартных
диалогах ограничивает начало слова. Направление, обход с начала и закрытие
диалога управляют навигацией. Стандартный regex-поиск выполняется вперёд:
обратное направление для него не поддерживается. Компактный поиск Context
работает в обе стороны и сообщает об обходе границы. Повтор поиска после
совпадения нулевой длины продвигается дальше.

Поиск следующего/предыдущего выделения использует выделенный текст либо
настроенный вариант: текущее слово/последний запрос. «Найти все» выводит строки
совпадений, «Отметить» добавляет временную подсветку. Замена меняет буферы,
поддерживает Undo; замена в сеансе затрагивает несколько открытых документов.
Перед сохранением проверьте каждый изменённый файл. Поиск проекта и Context
не заменяют содержимое файлов на диске.

## Обычный текст, escape-последовательности и нечёткий поиск

Без Regex запрос `a.b` ищет именно точку. В стандартных диалогах отдельный флажок
**Use escape sequences** преобразует `\t`, `\n`, `\r`, `\\`, `\uXXXX` в табуляцию,
перевод строки, возврат каретки, обратную косую черту и символ Unicode. Без этого
флажка последовательности буквальные. Regex подразумевает обработку escape в
этих диалогах. В компактных строках отдельного такого флажка нет: для поиска
символа табуляции или перевода строки через `\t`/`\n` включите Regex.

Только компактный текстовый поиск файла/Context/проекта понимает начальный `~`
при выключенном Regex. `~gctx` находит, например, `get_context`: символы Unicode
идут в том же порядке с произвольными промежутками, но в одной строке. Это не
исправление опечаток и не расстояние редактирования. Для буквального начального
`~` включите Regex и введите `~gctx`.

## Регулярные выражения (Regex)

Стандартные диалоги и компактный поиск Insight используют Perl-совместимые
выражения GLib. Вводите шаблон прямо в поле, без обрамления `/.../` и без
удвоения каждой обратной косой черты, как в строковом литерале C.

| Шаблон | Значение |
| --- | --- |
| `.` | Один символ, кроме перевода строки по умолчанию; `a.b` найдёт `a_b` |
| `\.` / `\\` | Буквальная точка / обратная косая черта |
| `[abc]`, `[a-z]`, `[^0-9]` | Набор, диапазон, отрицание набора |
| `\d`, `\w`, `\s` | Цифра, символ слова, пробельный символ; `\D`, `\W`, `\S` — отрицания |
| `\p{L}`, `\p{N}` | Буквы / числа Unicode |
| `^`, `$` | Начало / конец строки; сами текст не поглощают |
| `\bname\b` | Границы слова вокруг `name` |
| `x*`, `x+`, `x?` | Ноль и более, один и более, необязательный символ |
| `x{2,4}` | От двух до четырёх повторений |
| `.*?` | Ленивый повтор: кратчайшее подходящее совпадение |
| `cat|dog` | Один из вариантов |
| `(name)`, `(?:name)` | Запоминающая / незапоминающая группа |
| `(\w+)\s+\1` | Повтор того же захваченного слова |
| `(?=text)`, `(?!text)` | Положительная / отрицательная проверка вперёд |
| `(?<=x)`, `(?<!x)` | Проверка назад с ограничениями длины движка regex |
| `(?i)`, `(?s)`, `(?m)` | Без учёта регистра; точка включает перевод строки; построчные якоря |

Стандартные Найти/Заменить ищут построчно, пока не включён **Use multi-line
matching**. Многострочный режим рассматривает весь буфер; используйте `\n`,
`\r?\n`, `(?s)` по задаче. Компактный поиск Insight уже рассматривает весь текст
с построчными якорями: `^`/`$` обозначают границы каждой строки, но точка без
`(?s)` не включает перевод строки. Отрицательный набор `[^x]` может захватить
перевод строки; `[^x\r\n]` — нет. Case/Word действуют и в компактном Regex.
В стандартных Найти/Заменить при Regex флажки Whole word/Word start не применяются: задавайте границы через `\b` или проверки. Некорректный шаблон вызывает сообщение об ошибке. Regex ищет текст, а не AST
Python/C++; он может совпасть с комментарием, строкой и посторонним именем.

## Язык строки замены

В стандартной замене с Regex `\0` вставляет всё совпадение, `\1`–`\9` —
захваченные группы. Например, поиск `\bget_(\w+)\b`, замена `fetch_\1` превращают
`get_name` в `fetch_name`. Для буквальной обратной косой черты используйте `\\`.
`$1` и `${name}` не являются синтаксисом ссылок этого диалога. Без Regex замена
буквальная, кроме включённого Use escape sequences; эта опция позволяет вставлять
табуляцию и переводы строк. Пустая строка замены удаляет совпадение. Сначала
проверьте «Найти далее» и одну замену, затем «Заменить все»: regex способен
захватить пустую строку или гораздо больше текста, чем ожидалось.

## Keywords / Boolean: логический поиск

Этот режим поиска проекта включает отдельный разбор запроса и отключает обычный
переключатель Regex. Регистр операторов не важен; приоритет: NOT, AND, OR.

| Запрос | Смысл |
| --- | --- |
| `open file`, `open AND file`, `open + file` | Оба термина в заданном расстоянии строк |
| `open OR close` | Любой термин |
| `open NOT error`, `open !error`, `open -error` | Положительный термин без исключённого в окне |
| `(open OR close) AND file` | Явная группировка |
| `"open file"` | Буквальная фраза |
| `=Open` | Термин с учётом регистра независимо от общего Case |
| `~opfl` | Нечёткая подпоследовательность |
| `?"get_[a-z]+"` | Regex-термин; шаблоны с пробелами/скобками заключайте в кавычки |

Внутри кавычек `\"` означает кавычку, `\\` — обратную косую черту; остальные
regex-последовательности сохраняются. Word ограничивает обычные термины;
regex-термин сам задаёт границы. Для подсветки нужен положительный термин:
полностью отрицательный запрос не даёт подсвечиваемых результатов. Расстояние
терминов задаётся от 0 до 50 строк; 0 требует одной строки. Word variations
добавляет регулярные английские формы (`open/opens/opened/opening`, `save/saving`)
к подходящим базовым словам. Это не словарь, русская морфология или общий
стемминг; фразы, fuzzy и regex сохраняют свои правила. Ограничения: 32 термина,
128 узлов разбора, 16 уровней вложенного разбора; ошибки и превышения сообщаются.

## Фильтры символов/файлов и маски имён

Фильтры списков отличаются от текстового поиска. Термины через пробел
пересекаются; `~term` — подпоследовательность; `?pattern` — regex без учёта
регистра по имени символа или пути в файловом списке. `"name"` — точное имя,
`file:"полный путь"`, `scope:"полная область"` — точное поле. `@частьпути`
ограничивает путь, `scope=часть` — область. Завершающая `(` оставляет в фильтре
символов функции, прототипы и методы. Сопоставление без учёта регистра.

Маски файлов используют glob, не regex: `*` — произвольная последовательность,
`?` — один символ. Маски проектного поиска разделяются `;`: `*.c;*.h;*.py`.
Файловые фильтры также понимают glob-термины по сохранённым путям. Regex
`.*\.py$` предназначен для regex-фильтра, а не маски glob. Отдельные ограничения
масок Master File List описаны в [Project Files](panel-project-files.md).

## Результаты и пределы

Выбор результата показывает его в Context; Enter/двойной щелчок открывают файл.
Alt+Up/Down листают предпросмотр; Shift+F8/F9 — результаты. Stop оставляет
частичный результат. Изменившийся снимок исходника нужно искать заново перед
переходом к устаревшему совпадению. Компактный поиск Insight ограничен 2 МиБ
исходника и 1024 байтами UTF-8 в запросе; обход проекта и число результатов
имеют дополнительные пределы с сообщениями в интерфейсе. Context ищет только
загруженный предпросмотр. [Кнопки Context](panel-context.md).

## Области поиска ссылок

В режиме **Ссылки** доступны **весь текст**, **пропускать комментарии** и
**только комментарии**. Пропуск комментариев сохраняет строковые литералы:
`target` находится в `"target"`, но не в `// target`. Поиск только в комментариях
исключает строки. **References: code only** исключает и комментарии, и строки;
включение этого флажка сбрасывает список, а выбор фильтра комментариев снимает
флажок «только код».

Это лексические фильтры C/C++, JavaScript, Python, Lua и Shell. Тройные строки и
docstring Python остаются строками. В фильтрованных режимах неподдерживаемые
языки пропускаются; для них выберите «весь текст». Фильтры не вычисляют условия
препроцессора и не различают посторонние символы с тем же именем. Они действуют
для ссылок, а не текстового поиска проекта или замены. Места вызова по-прежнему
ищутся только в коде. Возврат восстанавливает фильтр ссылок; настройка сохраняется
между запусками. Выбор результата показывает исходный текст в Context с точной
позицией совпадения.
