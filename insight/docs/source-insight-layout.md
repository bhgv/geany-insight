# Интерфейс по руководству Source Insight 4

Эталон: [Window Tour](https://www.sourceinsight.com/doc/v4/userguide/Manual/Window_Tour/Window_Tour.htm),
[официальный скриншот](https://www.sourceinsight.com/doc/v4/userguide/assets/mainappwindow.png),
[Toolbars](https://www.sourceinsight.com/doc/v4/userguide/Manual/Window_Tour/Toolbars.htm),
[Project Window](https://www.sourceinsight.com/doc/v4/userguide/Manual/Command_Reference/Project_Window_command.htm).

| Область | Реализованное поведение |
| --- | --- |
| Слева | File Symbols активного документа, поиск фрагмента имени без учёта регистра, сортировка по имени, строке и типу. Используются текущие TM tags документа, включая несохранённые документы при наличии тегов. |
| Справа, Project Files | Поиск по фрагменту пути, сортировка по имени или полному пути, preview выбранного файла. |
| Справа, Folders | Иерархия каталогов индексированных исходников; каталоги перед файлами, алфавитная сортировка, раскрытие/сворачивание. Выбор файла показывает Context. |
| Справа, Project Symbols | Независимый от левой панели проектный список; поиск фрагмента имени без учёта регистра; сортировки по имени, строке и типу. |
| Справа, Usages | Существующий лексический поиск употреблений с проверкой снимка. |
| Справа, Symbol Categories | Тип тега → область видимости → символ. Поиск фрагмента имени, сортировка дерева, выбор/открытие через Context. Пока используются буквенные kind parser-а, а не единая семантическая классификация языков. |
| Справа, File Types | Группы синтаксисов Geany, определяемых по расширению; выбор файла показывает Context, Enter открывает исходник. |
| Снизу | Цветной Scintilla Context для выбранного файла/символа; Ctrl+click/F12 следует к известным определениям, Enter открывает текущую строку с центрацией. Выбор результата включает скрытый Context. |
| Сверху | Browse кнопки переходов назад/вперёд, определения, поиска проектных символов/файлов, открытия workspace и переиндексации; штатные кнопки Geany сохранены. |
| Меню | File, Edit, Search, Project, Options, Tools, View, Window, Help, Navigate, Scripts. Preferences и прежнее Document находятся в Options; Window перечисляет открытые документы. |

Ширина правой области и выбранная проектная вкладка сохраняются в настройках.
Штатные вкладки Geany слева остаются доступны, File Symbols выбирается при
инициализации workbench. Стандартные синтаксисы, кодировки, plugin API и Plugin
Manager сохраняются. Windows сборка и упаковка требуют `-Dplugins=true`;
плагины поставляются из той же сборки, а не из более старого GTK runtime.
Дисковое превью использует Geany encoding auto-detection с BOM; результат
ограничен 2 МиБ и не допускает NUL. Отдельная настройка кодировки файла в
основном редакторе продолжает работать, открытый буфер имеет приоритет.

Это реализованная компоновка и навигация, а не полное совпадение с Source
Insight. Правая проектная область может открепляться/возвращаться в док, с сохранением
геометрии и видимости. View > Panels управляет деревьями и активирует поля;
Layouts A–D переключают фиксированные компоновки (также кнопками toolbar).
Пока отсутствуют произвольные плавающие доки, отдельные переносимые группы
toolbar, Overview Scroller, семантическое Relation Window и полный
набор команд/параметров Source Insight. Категории пока группируют kind/scope
parser-а и не дают семантическое дерево членов класса. Иконки — стандартные
GTK theme icons. Поиск списков ограничен 500 проектными результатами и
2000 символами файла, категории — 5000 символами, дерево — 10000 файлами текущего manifest. После
восстановления кэша для файлов без тегов по-прежнему нужен Reindex.
Дерево показывает manifest распознанных исходников, а не произвольные
файлы диска. Контекстные панели пока не проверены интерактивно на целевых ОС.


Поиск в списках: `doc write`, `"WriteDoc"`, `?Write.*Doc`, `Write(`,
`scope=Widget @src/ write`. Регулярные выражения применяются к имени,
файловые — к полному пути. В Project Files доступны несколько фрагментов
и glob-маски (`*src/*.cpp`). Начальный `?` переключает regex. Все эти
фильтры отделены от Lua API: прежняя семантика index query API не меняется.
