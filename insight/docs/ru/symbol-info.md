# Сведения о символе

Откройте Навигация → Сведения о символе… на идентификаторе либо одноимённую команду под символами проекта/файла для выбранной строки. Немодальное окно содержит запрос имени/полного имени, список кандидатов, метаданные парсера и исходник Scintilla с подсветкой только для чтения.

Обновление запрашивает собственный снимок индекса и, если доступен, разбирает текущий файл редактора до 2 МиБ. Остальные файлы используют опубликованный индекс; после внешних правок переиндексируйте рабочую папку. Данные: имя/сигнатура, вид, записанный тип, область видимости, файл:строка и наследование. Отсутствующие данные пусты. До 512 кандидатов; сначала предпочитаются локальные/файловые, без обещания семантического разрешения перегрузок.

Исходник предпочитает открытые несохранённые буферы диску. Безымянные используют устойчивые ID документа. **Перейти** проверяет свежесть снимка, открывает выбранное место, центрирует его и закрывает окно. Изменённый/недоступный исходник требует обновления. **Использования** ищет имя в связях проекта и скрывает окно. **Скопировать сведения** копирует метаданные. Закрыть/Escape уничтожает окно.

Предпросмотр поддерживает существующее декодирование и лимит 2 МиБ. Выведение типов произвольных выражений, метрики сложности и полная семантика пока не перенесены; лексический размер определений описан ниже. Прокрутка исходника не изменяет его или основной редактор.

**Оставить файл открытым** загружает показанный файл в обычный буфер, оставляет окно сведений и восстанавливает предыдущий активный редактор, если он существует. Новый буфер позиционируется у определения. Для уже открытого исходника кнопка выключена. Те же проверки снимка защищают загрузку/переход. Файл появляется в списке окон. Ctrl+Enter выполняет переход; Ctrl+R обновляет при фокусе окна.

Проверка нативного редактора Linux и GUI подтверждает метаданные/исходник, UTF-8 пути, фоновое открытие закрытого файла, разбор/переход безымянного буфера, отклонение устаревшего снимка, предпросмотр/активацию/фильтр списка окон, отмену сохранения/закрытия и завершение. Проверка Windows GUI выполняется отдельно.

Refresh сохраняет выбранного кандидата по пути, строке, имени, виду, scope и сигнатуре, пока он присутствует в новом снимке. Явное открытие Symbol Info в другом месте задаёт новое предпочтение. Окно удерживает собственный снимок индекса для раскрытия записанных nominal-типов через aliases в scope объявления; неоднозначные или неизвестные типы не раскрываются.

Для завершённых функций с фигурными скобками, Python и Lua выводится размер в строках от строки определения до конца тела. Прототипы, неподдерживаемые/незавершённые тела и неуверенное совпадение нескольких функций на одной строке не получают размера. Это лексические границы исходника, а не оценка сложности или семантический AST. RU/EN GUI проверяет одно-/многострочные тела, отсутствие размера прототипа, тип alias и сохранение кандидата; Windows CI включает этот сценарий.

Для результатов функций C/C++ nominal-тип использует тот же resolver, что и Context: зависимый параметр шаблона не выбирает глобальный класс; явный `::T` и обычные результаты сохраняются. Выведение аргументов шаблонов остаётся открытым.

## Размер именованного определения

«Размер определения (строк)» показывается для завершённых именованных классов,
структур, объединений, перечислений, интерфейсов и пространств имён в лексических
буферах C/C++/C#/Java, а также классов Python. Диапазон начинается со строки
определения, указанной парсером, и заканчивается закрывающей скобкой тела либо
концом блока по отступам. Для открытых и безымянных буферов используется текущий
несохранённый текст. Прежний размер функций остаётся отдельным показателем.
Это размер участка исходника, а не оценка сложности или семантический AST.

Имя и вид объявления должны совпасть с заголовком исходника. Предварительные
объявления, namespace aliases, незавершённые тела, неизвестные заголовки и поздние
объявления на общей строке парсера остаются без размера. Поддержаны обычные
модификаторы, scoped enum, префиксы шаблонов C++ и списки базовых типов; сложные
макросы/атрибуты и специальные синтаксисы могут оставаться неизвестными.
Размеры классов/интерфейсов JavaScript/TypeScript отложены до расширения маски
регулярных выражений этих языков.
