# Границы текста

**Правка → Выделение и навигация → Границы текста** содержит девять команд и пункт справки. Они не меняют байты текста, состояние сохранения и историю отмены; поддерживается режим чтения. Существующие клавиатурные привязки не переназначаются.

![Рабочее меню в изолированной GUI-проверке Linux](../media/text-boundaries.jpg)

![Ступени перехода к границам строки и файла](../media/text-boundaries.svg)

| Команда | Результат |
| --- | --- |
| Умное начало строки | Из текста — к первому символу после пробелов/табуляции. Из отступа или его конца — к физическому началу строки. Из начала строки — к началу файла. |
| Умный конец строки | Из текста — за последний символ перед хвостовыми пробелами/табуляцией. Из хвоста или его начала — к физическому концу строки. Из конца строки — к концу файла. |
| Выделить до точки | От текущего anchor до позиции после следующей ASCII-точки (`.`), найденной от активного курсора. Если точек больше нет — до EOF. |
| Выделить до умного начала / конца строки | Те же ступени с сохранением anchor выделения. |
| Фрагмент слова влево / вправо | Штатное перемещение Scintilla по частям имени. При Extend Mode сохраняется anchor. |
| Выделить фрагмент слова влево / вправо | Штатное расширение выделения по части имени с сохранением anchor. |

Без Extend Mode умные переходы сворачивают обычное выделение в позиции назначения; при включённом режиме сохраняют anchor. Явные команды выделения не меняют состояние Extend Mode. Используется активный конец, включая обратное выделение. Позиция назначения показывается в редакторе.

На строках из пробелов/табуляции умное начало ведёт к началу строки, затем файла; умный конец — к концу строки, затем файла. На пустой строке физическая граница уже достигнута, поэтому переход сразу ведёт к границе файла. Используются физические строки, независимо от визуального переноса. Пробельные символы у границ — ASCII-пробел и табуляция; окончания строк исключены из содержимого строки.

Команда выделения до точки использует простой поиск следующей точки. Дроби, строки, комментарии и сокращения не разбираются. Поиска назад до грамматического начала предложения нет.

Части имён используют существующую классификацию Scintilla: `Create|Window`, `HTML|Open`, `open|_file`, `Vip|32|Test`. Переход вправо с `_` пропускает разделитель и проходит следующий фрагмент. Пробелы и пунктуация образуют отдельные штатные группы. Непрерывный не-ASCII-текст обрабатывается как одна штатная группа; лингвистическое разбиение Unicode не добавлено. Эти правила перемещения отличаются от индексации имён Source Insight, которая может объединять цифры с предыдущим фрагментом.

Только одно обычное выделение: прямоугольные, множественные и виртуальные пробелы исключены. Умные границы и выделение до точки требуют UTF-8 без NUL, корректных границ символов/CRLF и документа не более 8 МиБ. Штатные команды фрагментов не копируют весь документ и не имеют этого ограничения. Ошибка проверки или неподдерживаемый режим сохраняют выделение.
