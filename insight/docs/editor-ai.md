# ИИ-помощник исходника и проекта

Откройте **Tools → Editor / Project AI Assistant…** с нужным исходником. Помощник работает непосредственно в существующем Diff/Merge. Настройки API общие с [помощником консоли](console-ai.md): OpenAI/ChatGPT API, Grok, DeepSeek, Qwen и совместимые серверы; требуются Python 3, ключ и ID модели. Раскройте **API settings**, чтобы изменить их. Ключи остаются в памяти, в настройках сохраняются только адрес, провайдер, модель и Python.

![Запросы, варианты и ручная проверка](media/editor-ai.svg)

## Задачи и накопление требований

Выберите стандартную задачу и нажмите **Add standard task** либо напишите свой запрос в многострочном поле. Доступны проверка синтаксиса и диагностик, логики и граничных случаев, форматирование, улучшение решения, читаемые имена функций/переменных/классов/структур/макросов, алгоритмы, справка по функциям, полезные комментарии и документация.

**Add request and generate variant** отправляет новый запрос вместе со всеми требованиями выбранного варианта, текущим редактируемым Result, путём целевого файла и показанным проектным контекстом. Новые требования дополняют старые. Раздел **Accumulated requirements for this variant** показывает полный список. Старые объяснения не подменяют требования. Во время запроса Result заблокирован; **Cancel request** сохраняет прежний вариант и текст нового запроса. Закрытие окна также отменяет запрос.

Это анализ модели, а не запуск компилятора или тестов: сообщения о синтаксисе и логике требуют проверки. Встроенные задачи просят объяснять доказательства и неопределённость, сохранять контракты и отмечать изменения, необходимые в других файлах. Ответы без структурированного предложения показываются как объяснение без замены кода.

## Варианты, Undo/Redo и ручные правки

Слева показан захваченный исходник, справа — вариант, а **Result можно редактировать вручную**. Успешный ответ сразу помещается в Result для проверки; исходный документ остаётся прежним. Следующий запрос использует именно Result, включая ручные исправления.

- **Undo variant / Redo variant** восстанавливают код, накопленные требования и объяснение вместе. Ручные изменения Result сохраняются отдельным вариантом перед следующим запросом или переходом по вариантам. Новый запрос после Undo создаёт новую ветвь истории и убирает прежний Redo.
- Обычные **Undo / Redo** Diff/Merge относятся к ручным изменениям Result и операциям выбора блоков внутри текущего сравнения.
- Для каждого файла хранятся до 32 вариантов в памяти. Переключатель файла сохраняет его Result и возвращает собственную историю.

**Apply Result to Source** переносит результат в исходный буфер одним Undo, только если источник совпадает с захваченным снимком и доступен для записи. Закрытый/переименованный или изменённый источник не заменяется молча. Файлы автоматически не сохраняются и по SSH не загружаются. После применения используйте обычные сохранение и проверку проекта.

## Открытие в редакторе и обновление

**Open source in editor** выбирает исходный документ в главном редакторе, не закрывая ИИ Diff и не применяя Result. Правьте исходник в обычном редакторе и затем нажмите **Refresh sources** в ИИ Diff. Обновление явное: возвращение фокуса ничего не перезаписывает.

Обновляются выбранные исходники — из открытых буферов, включая несохранённые изменения, либо с диска. Result и история вариантов сохраняются; левый снимок обновляется. Автоматически подготовленный и не отредактированный проектный контекст также пересобирается. Пользовательский контекст сохраняется. После обновления сравните новый исходник с оставленным Result и применяйте только нужные изменения. Для закрытого сохранённого файла явное обновление разрешает перечитать его с диска; переименованный открытый документ нужно добавить заново.

## Проверка проекта

**Project files…** показывает фактический список файлов проиндексированного проекта. Дождитесь завершения индексации, выберите нужные файлы и нажмите **Add selected files**. **Add current file** добавляет текущий открытый буфер. **Remove file** убирает выбранный файл из этой сессии; после удаления пересоберите контекст при необходимости.

**Prepare project context** собирает полные снимки остальных выбранных файлов. Раскройте **Project context sent with each request** и просмотрите/отредактируйте отправляемый текст. Сам выбор файлов и подготовка контекста ничего не отправляют. Для каждого целевого файла контекст можно подготовить заново. Изменения предлагаются и применяются по одному файлу; для другого файла выберите его и задайте задачу. Автоматических многофайловых патчей и запуска команд нет.

Одна сессия — до **16 файлов**; один полный UTF-8 исходник/Result — до **128 КиБ**, общий проектный контекст запроса — до **64 КиБ**, новые требования — до **4 КиБ**, накопленные требования — до **16 КиБ**. Превышение отклоняется без молчаливой обрезки. Это проверка выбранной группы, а не обещание анализа всего большого проекта. Файлы других групп можно проверить отдельными сессиями.

## Частые и последние запросы

В **Recent and frequent requests** находятся до 20 последних и до 20 наиболее частых запросов. Выбор добавляет текст в поле нового запроса, не отправляя его. Стандартные задачи также добавляются к набранному тексту.

При включённом **Remember request text for recent/frequent lists** успешные новые запросы, число использований и время сохраняются локально в приватном `insight-ai-prompts.conf` (до 64 записей). Код, ответы и ключ API туда не записываются. Отключите флажок, если текст текущих запросов не должен попадать в списки. Варианты, код и накопленные требования существуют только в памяти окна.

## Проверка реализации

Регрессионный тест ядра проверяет накопление требований, Undo/Redo, ветвление вариантов, ограничения и сохранение частоты запросов. Нативный Linux-тест работает с полным редактором, реальным проектом и локальным mock API: проверяет проектный контекст, передачу ручного Result, накопление запросов, варианты, переход в редактор, обновление без потери Result, запрет устаревших/readonly правок, один Undo, неизменность диска, списки запросов и отмену. Живые провайдеры без ключей, Windows и Android не проверялись.


Задача **Project consistency** проверяет целевой файл вместе с выбранным контекстом и перечисляет основания и необходимые межфайловые исправления. Текст стандартных задач следует выбранному языку интерфейса.


**Recompare variant** повторяет отменённое/неуспешное сравнение без потери сохранённого варианта. Если сравнение готово, сначала сохраняются ручные правки Result.
