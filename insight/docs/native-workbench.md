# Geany Insight 0.8: встроенный workbench

Этапы 27–56 содержат 30 отдельных Git-коммитов. Начиная с этапа 33 интерфейс
реализован в `src/insight-workbench.c` и линкуется в libgeany. Он создаётся
libmain и работает при отключённых плагинах (`geany --no-plugins`). Native
изменения подключены к editor.c, document.c, callbacks.c и ui_utils.c.

## Интерфейс

Нижний Context — отдельный read-only Scintilla. Он показывает полный исходник
с исходными номерами строк, подсветкой lexer-а и центрированием определения.
Открытый буфер, в том числе несохранённый, имеет приоритет над файлом на диске.

Follow cursor показывает определение известного символа под курсором; без
известного определения показывает текущую строку. Ctrl+click в preview
(Primary-click на macOS) проходит к определению и закрепляет контекст. Если
известно несколько кандидатов, их можно выбрать в выпадающем списке. Open
source / Enter открывает контекст в основном редакторе и центрирует строку.
Back/Forward хранит до 64 ручных переходов. View → Context window скрывает
панель независимо от Messages.

Workspace — поиск символов по префиксу и outline текущего файла. Выбор строки
показывает preview; двойной щелчок открывает определение. Project files ищет
файлы по подстроке. Usages ищет целый идентификатор по одному файлу за idle с
отменой и опцией Current buffer only. SHA256 снимка защищает выделение
совпадения от использования устаревших byte offsets. Поиск употреблений
лексический: строки/комментарии включены, область видимости не разрешается.

Первый запуск показывает Workspace и Context вместо Messages. Build скрыт;
сборка пользовательских проектов не входит в новые функции. Старый upstream
код сборки остаётся в дереве. Интерфейс получает собственные Navigate и Scripts,
а заголовок приложения — Geany Insight. Стили панели используют текущую GTK-тему.

| Действие | Клавиша |
|---|---|
| Известное определение | F12 / Primary-click в основном редакторе |
| Поиск символа | Primary+Alt+S |
| Поиск файла | Primary+Alt+O |
| Поиск употреблений | Primary+Alt+R |
| История контекста | Primary+Alt+Left / Right |
| Палитра Lua | Primary+Shift+P |

## Проект и сохранение

Source folder выбирает корень без файла проекта и без запуска make/cmake.
Обход ограничен 10 000 файлами, 2 МиБ на файл и глубиной 64; символы ограничены
250 000. Скрытые и служебные каталоги и симлинки пропускаются. Cancel scan
оставляет частичный индекс; Reindex отражает внешние изменения и удаления.
Файлового watcher пока нет. Разбор и чтение одного файла синхронны в главном
потоке: idle-обход даёт отмену между файлами, но не строгую гарантию отсутствия
задержек на отдельном файле.

В `configdir/insight/workspace.idx` сохраняется дисковый индекс после успешного
завершённого обхода. Snapshot ограничен 64 МиБ, имеет CRC32 и проверку формата.
Открытые буферы — overlay, который не записывается в snapshot. После закрытия
файла overlay исчезает при следующем запросе. Восстановленный список файлов
содержит только файлы с тегами: Reindex восстанавливает полный manifest,
включая исходники без символов. Кэш не гарантирует актуальность диска.

`configdir/insight/workbench.conf` хранит splitter, Follow cursor, видимость
и root; `lua-extension.conf` хранит автозагрузку Lua. Настройки native workbench
отдельны от legacy plugin. Превью дисковых файлов требует UTF-8 без NUL;
открытые документы используют уже преобразованный редактором UTF-8 буфер.

## Встроенный Lua

Scripts содержит Load/Reload/Unload extension, Run script, Commands и палитру.
Используется Lua 5.4.8 и API 0.8: диапазоны, курсор, файлы, строки, поиск
употреблений, страницы файлов и расширенные запросы символов. См. lua-api.md.
Native вызов получает отдельный снимок индекса, состояние расширения сохраняется,
правки объединяются в Undo. Документные события read-only; события во время
выполнения другой Lua-команды пропускаются. io/os/package/debug запрещены;
16 МиБ Lua-памяти и бюджет инструкций остаются ограничениями, а не строгой
песочницей. Пример — `examples/workbench.lua`.

## Сборка редактора

Нужны C/C++, Meson/Ninja, pkg-config, GLib/GTK3 development packages и gettext.

```sh
meson setup build-native --prefix="$PWD/run-native" --libdir=lib \
  -Dhtml-docs=disabled -Dpdf-docs=disabled -Dapi-docs=disabled \
  -Dgtkdoc=false -Dvte=false
meson compile -C build-native
meson install -C build-native
run-native/bin/geany --new-instance --no-plugins --config "$PWD/native-profile"
```

Autotools metadata также дополнено native/Lua исходниками; Autotools-сборка
в этой среде не запускалась. CMake в insight собирает переносимое ядро,
Android JNI или legacy plugin; native desktop UI собирается вместе с Geany.
Старые проверочные архивы 0.7 не содержат нового native UI — для него нужен
редактор из текущего дерева.

## Проверки и оставшаяся работа

Проверены полная Linux x64 сборка Geany, девять core-тестов в CMake с UBSan
и в отдельном compiler runner, native tag adapter (в том числе UBSan), GIO
cache/extensions с UBSan, JNI на JDK 17 с -Xcheck:jni и восемь примеров парсеров.
Полная Windows x64 кросс-сборка включает новый libgeany-0.dll, EXE,
Context, индекс и встроенный Lua. Проверены PE x64 и именованные импорты
EXE/DLL относительно поставляемого GTK runtime; собраны девять core-test EXE.
Интерактивные сценарии GUI и исполнение Windows EXE на целевой машине
не проверены; macOS и Android workbench требуют отдельной проверки/реализации.
APK в этой серии не собирался.

Это встроенная основа интерфейса и навигации в направлении Source Insight.
Точное разрешение типов/областей видимости, семантические ссылки, call graph,
полнота всех стандартов C/C++ и диалектов ассемблера ещё не реализованы.
Поддержка извлечения символов и подсветки зависит от штатных parser/lexer Geany.

## Переносимая проверочная сборка Windows x64

В текущих исходниках Context сохраняет прокрутку и выделение при неизменных
тексте, типе файла и целевой строке. Enter/Open source открывают строку
каретки превью. F12 внутри превью действует как Ctrl+click: следует по
определению с записью истории. Цвет текущей строки соответствует схеме
подсветки; кнопки истории отключены на её границах. Эти изменения появились
после выпуска проверочного Windows архива 0.8.

Дополнительно: Enter в поиске символа/файла открывает первый результат,
Down переводит фокус в таблицу, Escape возвращает в основной документ.
Щелчок в Context закрепляет превью, выключая Follow cursor. Wrap переносит
длинные строки и сохраняется вместе с режимами outline и current buffer.
Copy location копирует адрес каретки в виде `file:line`. Открытие выбранной
строки списка заново проверяет её Context; Usages проверяет снимок и при
активации строки. При изменении текста источника Context отказывает в
переходе до обновления превью (BOM/CRLF нормализуются только для проверки
перехода по строке, байтовые совпадения Usages проверяются без нормализации).

Запуск `Start-Native-Insight.cmd` создаёт отдельный `profile` рядом с программой.
Дополнения отключены при запуске: Context и Scripts являются частью редактора.
`Run-Checks.cmd` запускает девять проверок ядра. Архив содержит GTK runtime,
русские переводы, примеры Lua, документацию и Git bundle с полными исходниками.

Для сборки используется Meson cross-file с MinGW-w64 C/C++/windres и Windows
GTK3 SDK; `windres` должен использовать именно целевой GCC с `-E -xc -DRC_INVOKED`.
Опции: `-Dplugins=false -Dsocket=true -Dvte=false -Dhtml-docs=disabled
-Dpdf-docs=disabled -Dapi-docs=disabled -Dgtkdoc=false`, C/C++ link flags
`-static-libgcc -static-libstdc++`. После `ninja` упаковка выполняется
`insight/tools/package_native_windows.py --runtime GTK_RUNTIME --build MESON_BUILD
--checks CORE_CHECKS --bundle GIT_BUNDLE --out OUTPUT --strip MINGW_STRIP`.
Обе программы `bin/geany.exe` и `bin/libgeany-0.dll` берутся из новой сборки;
штатный Geany из runtime заменяется. В `build-info.json` указан Git commit.
