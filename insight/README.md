# Geany Insight — прототип 0.5

Основа: Geany commit `1565953ccdc0f23f14edb4158ef42cc7e493d711`.
Lua: 5.4.8, исходники включены, загрузка зависимостей не требуется.
Лицензия новых компонентов GPL-2.0-or-later; Lua — MIT.

## Реализовано

* Общее C99-ядро Lua и индекс символов без зависимости от GTK.
* Lua API: `editor.text()`, `editor.selection()`, `editor.replace_selection(text)`.
* `project.symbols(prefix, exact)` возвращает таблицу до 256 результатов и полное
  число совпадений. Поля: name, path, scope, kind, line (строки начинаются с 1).
  По умолчанию поиск по префиксу; exact=true — точное имя. Сравнение регистрозависимое.
* Адаптер Geany: Tools → Insight: Run Lua script… с выбором скрипта и единым Undo.
* Lua-расширения: commands.register(id, label, callback) добавляет именованную
  команду в меню Geany. Состояние Lua сохраняется между вызовами. Неудачная
  загрузка нового расширения сохраняет старые команды. См. docs/lua-api.md.
* Lua API версии 0.5; 128 команд на расширение, отдельный бюджет инструкций
  на загрузку и каждый вызов, общий предел Lua-памяти 16 MiB.
* Tools → Insight: Project navigation → Index source directory…: рекурсивный
  обход исходников и разбор штатными парсерами Geany без запуска сборки проекта.
* Find symbol…: фильтр по префиксу, имя/область/файл/строка/вид символа,
  переход двойным щелчком или кнопкой Go to. Используется история переходов Geany.
* Cancel indexing: остановка с сохранением частичного индекса.
* Снимок последнего завершённого обхода каталога сохраняется в
  конфигурации Geany и восстанавливается при загрузке плагина. Команда
  Reindex current directory повторно сканирует сохранённый каталог.
* Снимок имеет версию, CRC32, предел 64 MiB, до 250 000 символов и 64 KiB
  на строковое поле. Повреждённые/усечённые данные отклоняются. Формат одинаков
  для платформ с разным порядком байтов. CRC32 проверяет повреждения, не подлинность.
* Несохранённые теги открытых документов добавляются только в текущий поиск;
  на диск сохраняются результаты разбора файлов с диска. После закрытия документа
  при следующем поиске восстанавливаются теги дискового снимка.
* Атомарная замена символов отдельного файла; индекс владеет копиями строк,
  поэтому освобождение тегов парсера не оставляет висячих указателей.

## Сборка и запуск

Требуются C99-компилятор и CMake. Для настольного модуля нужны Geany development
headers, GTK3 development headers и pkg-config.

```sh
cmake -S insight -B build-insight -DINSIGHT_GEANY_PLUGIN=ON
cmake --build build-insight
ctest --test-dir build-insight --output-on-failure
```

Скопируйте модуль insight_lua в каталог плагинов Geany (на Linux обычно
~/.config/geany/plugins), включите его в Tools → Plugin Manager.
Выберите каталог через Project navigation → Index source directory…, дождитесь
сообщения о завершении, затем откройте Find symbol…. Для повторной индексации
используйте Reindex current directory либо выберите каталог ещё раз. Без выбора каталога поиск использует теги открытых файлов.

Для примера Lua выделите текст и запустите examples/uppercase.lua.
examples/find_symbols.lua показывает запросы к индексу.
На Windows/macOS нужны соответствующие SDK Geany/GTK и конфигурация toolchain.
Ядро отдельно собирается без GTK:

```sh
cmake -S insight -B build-core
cmake --build build-core
ctest --test-dir build-core --output-on-failure
```

Проверка без CMake:

```sh
python3 insight/tests/run.py
SANITIZE=undefined python3 insight/tests/run.py
```

## Проверено в текущем окружении

* Сборка CMake и CTest: 5 из 5 тестов проходят.
* Обычные тесты и UBSan: Lua, ошибки, лимиты, поиск из Lua, атомарное обновление
  индекса, удаление файлов и 500 обновлений с независимой моделью результатов.
* Снимки: повторная сериализация даёт те же байты, сохранены кириллица и спецсимволы
  путей; проверены все усечённые варианты и повреждения каждого байта малого снимка,
  неверная версия, контрольная сумма, число записей, длины полей и номера строк.
* Отдельные GIO-тесты кэша проходят с UBSan: запись/чтение, замещение снимка,
  сохранность предыдущего кэша при ошибке, повреждённый и отсутствующий файл.
* Lua-команды: регистрация, замыкания и повторные вызовы, смена текущего host,
  сохранность старого расширения при ошибках загрузки, лимиты памяти/инструкций,
  отказ дубликатов/поздней регистрации и восстановление вызовов после ошибки.
* Настольный модуль скомпилирован с -Wall -Wextra -Werror и слинкован с
  Geany 2.0/GTK3, включая проверку разрешения символов линкером.
* Реальные парсеры Geany: примеры C, C++, Python, Lua, JavaScript, shell,
  ASM и Make успешно дают ожидаемый символ (tests/geany_parsers.py).
  Это проверка извлечения тегов; GUI и весь обход каталога этим не проверяются.
* Полный GUI-сценарий Geany, Windows и macOS пока не проверены.
  NDK-сборка Android проверена в версии 0.3.
* ASan: чистого результата нет. Ранее runtime получил stack-buffer-underflow
  вместе с предупреждением __asan_handle_no_return; проверка отдельного индекса
  остановлена LeakSanitizer из-за недоступности /proc/task в окружении.
  Проверку нужно повторить вне этого окружения.

## Ограничения прототипа

Сохраняется один последний дисковый индекс: <configdir>/plugins/insight/project.idx.
Снимок обновляется после завершения обхода. Отмена, лимит файлов и ошибка обновления индекса
не заменяют предыдущий кэш. Теги несохранённых документов в кэш не попадают.
Загрузка и сохранение снимка пока синхронные; крупный индекс может задержать UI.
Постоянного файлового watcher нет: внешние изменения и удаление файлов отражаются
после Reindex current directory. Восстановленный индекс — снимок, а не гарантия
актуальности исходников. Перед поиском, Lua-скриптом и командой обновляются теги открытых именованных
файлов, включая файлы вне выбранного каталога; они могут отставать от текста до
очередного разбора Geany. После закрытия документа его временные теги убираются
при следующем поиске, остаются данные дискового снимка.

Обход проходит по одному элементу каталога на idle-событие. Разбор отдельного
файла и обновление сортированного индекса синхронные; задержки UI ещё возможны.
Ограничения: до 10 000 разобранных файлов, 2 MiB на файл, глубина 64 каталога;
симлинки, скрытые элементы, node_modules и __pycache__ пропускаются.
Окно показывает первые 500 совпадений. kind — буква вида символа от парсера.
Навигация использует снимок номера строки, поэтому после правок нужна актуализация.

Парсеры дают определения и объявления, а не семантический поиск использований.
Точность и языки зависят от парсеров установленного Geany и конфигурации filetypes.
Специализированная поддержка диалектов ассемблера, ash, CMake и всех стандартов
C/C++ пока не добавлена. Языковые серверы ещё не подключены.

Одноразовый Lua-скрипт получает новое состояние на каждый запуск. Расширения
с именованными командами сохраняют состояние до замены или выгрузки. Загрузка
расширения не получает доступа к editor/project API. Подробности: docs/lua-api.md.
Lua-файлы настольного адаптера ограничены 256 KiB. Лимит аллокатора — 16 MiB,
лимит выполнения — около миллиона Lua-инструкций. Нет io/os/package/debug/coroutine,
загрузчиков файлов и pcall/xpcall. Метатаблицы с __gc запрещены: Lua отключает
instruction hooks внутри финализаторов. Это не строгая песочница: C-функции и host
callbacks не прерываются счётчиком инструкций. Лимит памяти относится только к Lua.
Изменения до ошибки сохраняются и отменяются одним Undo. Встроенный NUL в
заменяемом тексте не поддерживается. API использует UTF-8; uppercase — только ASCII.

## Android и дальнейшая работа

Добавлен Android-редактор с системными диалогами файлов, Lua/JNI, одношаговым
Undo и черновиками. Построен debug APK для ARM64, ARMv7 и x86-64; native-сборка,
Java-компиляция, подпись и выравнивание проверены. На устройстве ещё не запускался.
См. android/README.md для команд сборки, ограничений и ручной проверки.

Новая общая модель документа на C проверяет UTF-8 и границы выделения.
CTest: 5 из 5 тестов проходят; обычные тесты и UBSan проходят. JNI проверен на
JDK 17 с -Xcheck:jni. Android пока не подключает проектный индекс и не имеет подсветки.

Следующие этапы: проверка Android на устройстве и GUI Geany; подсветка и вкладки
Android; файловый watcher и фоновая актуализация индекса; LSP транспорт; поиск использований,
окно контекста и иерархия вызовов; автозагрузка Lua-расширений, горячие клавиши и события редактора.

APK собирается только по явному запросу и по умолчанию только для ARM64.

Целевые ОС: Linux, Windows, macOS, Android с запуском самого редактора.
Целевые языки: C/C++, Python, Lua, JS/TS, Bash/ash, CMake/Make, ассемблер
x86/x64, ARM/ARM64, RISC-V/RISC-V64. Список должен быть расширяемым.
Сборка пользовательских проектов не входит в цели.

## Дополнительная проверка desktop-кэша

При наличии GIO development headers:

```sh
cmake -S insight -B build-cache -DINSIGHT_CACHE_TESTS=ON
cmake --build build-cache
ctest --test-dir build-cache --output-on-failure
```

Дисковое замещение использует GIO g_file_replace_contents; гарантии зависят от ОС
и файловой системы. Источник API: https://docs.gtk.org/gio/method.File.replace_contents.html
Полный GUI-сценарий восстановления и повторного обхода ещё не проверен.
