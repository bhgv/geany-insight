# Проверка отладчиков Lua и Python в Geany Insight

Комплект рассчитан на ручную проверку собранного редактора. Ожидаемые остановки
обозначены комментариями в исходниках, поэтому после правки ориентируйтесь на
метку, а не на номер строки в этой инструкции.

| Файлы | Назначение |
|---|---|
| `lua_main.lua`, `lua_worker.lua` | Программа Lua и отдельный модуль |
| `python_main.py`, `python_worker.py` | Та же программа на Python |
| `python_console.py` | Ввод кириллицы, пустой строки и EOF |
| `observe_calls.lua` | Журнал аргументов и карточка счётчика |
| `observe_sequence.lua` | Остановка по последовательности вызовов |
| `observe_graph.lua` | Вычисляемая карточка из вложенного графа |

## 0. Подготовка

Скопируйте всю папку в рабочий каталог и создайте из него проект Geany.
Корнем проекта должна быть папка с `lua_worker.lua`: оттуда Lua-отладчик
разрешает `require("lua_worker")`. Для Python нужен Python 3. Для шага 6
нужен Git в `PATH`. Файлы `observe_*.lua`
загружайте через **Conditions and Script… → Load Lua… → Apply**.

Откройте `lua_main.lua` или `python_main.py` и выберите
**Scripts → Debug Current Lua Buffer…** или **Debug Current Python Buffer…**.
Повторите шаги 1–7 для обоих языков. Когда переходите к другому сценарию,
закройте окно отладки или нажмите Ctrl+F5, затем проверьте **All Breakpoints…**:
точки сохраняются между запусками. Для сценария, который должен выполняться
без пауз, отключите другие точки и очистите верхнее поле в **Conditions and
Script…**. При открытии нового окна восстановленный черновик включается
только после **Apply**.

## 1. Точка в модуле, кадры и переход к исходнику

1. На первой паузе нажмите **Breakpoints in File…**, выберите соответствующий
   `*_worker` и укажите строку с `WORKER_STOP` (Lua 12, Python 13).
2. Нажмите F5. Должен открыться модуль. Значения `value`, `increment` и
   `next_value` в первом вызове равны 0, 1 и 1. Наведите мышь на `next_value`
   в исходнике, чтобы проверить подсказку.
3. В **Stack and locals** выберите вызывающий кадр. Должна выделиться
   `CALL_SITE` в основном файле. В **Watch graph** найдите локальную
   `state`. Связи `device` и `alias` ведут к одному узлу, а `self` возвращает
   к `state`. Попробуйте закрепить вложенный `status`.
4. Нажмите **Go to Source**, чтобы открыть строку в редакторе. Вернитесь в
   окно отладки и нажмите Shift+F11. Шаг выполняется из фактической остановки
   в модуле. На следующей паузе снова выбран кадр №0.

## 2. Условная и журнальная точки

1. Перезапустите программу и снова остановитесь на `WORKER_STOP`. Щёлкните
   по номеру строки с Shift и задайте условие
   `event.locals.next_value >= 10`, порог **2** и режим остановки.
2. Перезапустите и нажмите F5. Первое значение 1 не совпадает. Значение 10
   даёт первое совпадение. Остановка должна наступить на значении 12.
3. В **All Breakpoints… → Edit Rule** смените порог на **1** и включите
   **Log hits and continue**. Перезапустите и нажмите F5. В **Observer log**
   должны появиться две записи для `WORKER_STOP`, с `hit 1` и `hit 2`.
4. Отключите точку через **All Breakpoints… → Enable / Disable** и повторите
   запуск. Записей от этой точки быть не должно. Перед следующим шагом
   удалите правило через **Edit Rule → Remove Rule** и отключите обычную
   точку на `WORKER_STOP`, если она снова видна в списке.

## 3. Журнал вызовов и остановка по последовательности

1. После перезапуска загрузите `observe_calls.lua` и нажмите F5.
   Ожидаемый журнал в обоих языках:

   ```text
   tick(0, 1)
   tick(1, 9)
   tick(10, 2)
   ```

   В графе после завершения должна остаться карточка **Worker calls** со
   значением **3**. Python выводит 12 в **Console**.
2. Перезапустите, замените обработчик на `observe_sequence.lua` и нажмите F5.
   Должна появиться запись `Matched tick(0, 1) -> tick(1, 9)`. Остановка
   наступает на ближайшей доступной строке второго вызова. Проверьте
   аргументы `value = 1` и `increment = 9`.

## 4. Вычисляемый граф

Перезапустите, загрузите `observe_graph.lua` и поставьте обычную точку
на `FINAL_STOP` в основном файле (Lua 26, Python 27). После F5 в графе
должна быть карточка **Double device status = 42**. Для проверки смены кадров снова включите точку на `WORKER_STOP` и
перезапустите. В кадре модуля карточки быть не должно. Выберите вызывающий
кадр со `state`: карточка должна появиться со значением **42**.

## 5. Ввод в Python

Откройте `python_console.py` и запустите отладку. Очистите активное условие и
сценарий, если они включены, затем нажмите F5. На первом запросе введите
`Привет`, на втором нажмите Enter с пустым полем, на третьем нажмите
**Send EOF**. Ожидаются `empty_length=0` и `EOF received`.

## 6. Отдельная Git-история

1. На паузе задайте условие `event.locals.next_value == 10`, загрузите
   `observe_calls.lua` и нажмите **Commit Draft…**. Дайте коммиту имя
   `smoke-v1`. Для проверки набора правил заранее оставьте хотя бы одну
   условную точку, например отключённую журнальную точку из шага 2.
2. Измените условие на `event.locals.next_value == 12`, смените сценарий
   на `observe_sequence.lua` и сделайте коммит `smoke-v2`.
3. Через **Git History… → Load Draft** откройте `smoke-v1`. Проверьте
   текст условия и сценария. **Apply** также восстанавливает набор правил,
   если все его точки привязались к исходникам.
4. Отредактируйте старый черновик и сделайте новый коммит. Проверьте,
   что в истории видны все три записи. Git исходников проекта не должен
   получить этих коммитов.

## 7. Перенос точки после правки

Поставьте и сохраните точку на `FINAL_STOP`. Закройте отладчик, вставьте
несколько строк выше неё, сохраните файл и откройте отладку снова. Точка
должна остаться на метке `FINAL_STOP` с новым номером. Затем удалите саму
строку и повторите запуск. Счётчик неразрешённых точек должен увеличиться,
а на прежнем номере остановки быть не должно.

При сбое запишите язык, шаг, ожидаемый и фактический результат. Если
редактор не собрался, приложите журнал из `RootDir\logs` и ревизию исходников.
